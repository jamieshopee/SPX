# SPX 入口平台 — Architecture Contract v1.0
Status: Locked

## 文件性質

本文件是 SPX 的 Architecture Contract，不是 Implementation Spec。它定義 SPX 的整體組成、責任邊界、工具分離原則、主要操作流程與已確認的擴充邊界。

本文件不規定實體工具資料夾名稱、registry 的檔名、格式或 schema，也不規定程式與資料的內部拆分。後續實作必須遵守本文件；若要改變本文定義的架構邊界，應先修訂並重新確認本 Architecture Contract。

## 產品定位

SPX 是工具入口平台。專案根目錄為 `/Users/jamie/Documents/SPX`，本文件位於 `docs/架構說明.md`。

目前 SPX 包含兩個同級工具：

- 開獎秀
- 快速取件

未來可新增與兩者同級的新工具。

SPX AD 是獨立既有專案，不屬於本 SPX 入口平台。

## 整體邏輯架構

```text
SPX 入口平台
├── 開獎秀
│   └── 項目清單
│       ├── 線上／電子BN
│       ├── OM
│       ├── 直播
│       └── 門市清單
└── 快速取件
```

此結構使用邏輯名稱描述，不鎖定「開獎秀」與「快速取件」的正式英文資料夾名稱。

SPX 根層工具清單與開獎秀內部項目清單屬於不同層級，兩者不得混為同一個 registry 概念。

## SPX 入口平台責任

SPX 首頁只負責：

- 管理可進入的同級工具。
- 顯示工具入口。
- 將使用者導向所選工具。

SPX 首頁不理解或管理各工具內部的項目、視覺、Excel 規則、版位、版型、素材或產生流程。

## 工具資料驅動原則

SPX 根層工具清單採資料驅動。工具入口不得直接寫死為首頁內部的固定工具邏輯。

未來新增同級工具時，應新增獨立工具並登記於根層工具清單，不應要求首頁理解該工具的內部功能。

本 Architecture Contract 不鎖定根層工具清單的實際檔名、格式或 schema。

## 工具分離原則

每個 SPX 工具都是獨立單元，各自管理自己的功能、工單、版型、素材與程式。

正常情況下：

- 修改一個工具不需要修改其他工具。
- 新增、修改或移除某工具的內部項目、視覺或版位，不應改變其他工具的內部架構。
- 入口平台不直接依賴任一工具的內部實作。

本 Contract 不要求每個工具機械式具備完整的 `js/`、`css/`、`forms/`、`templates/`、`assets/` 資料夾組合。各工具實際需要的資料夾及內部拆分由後續 Implementation 決定。

## 共用字型原則

正式 Web 字型是 SPX 根層共用資源。各工具使用根層正式字型，不得在各工具內重複保存相同的正式字型。

除正式 Web 字型外，目前不建立其他跨工具共用依賴。各工具的工單、版型、素材與程式仍由工具自行管理。

## 開獎秀

### 工具定位

開獎秀是一個完整且獨立的 SPX 工具，只有一套共用控制中心。

目前包含四個項目：

- 線上／電子BN
- OM
- 直播
- 門市清單

未來可新增項目。項目清單採資料驅動，不把項目直接寫死在 HTML。

每個項目有自己獨立的 Excel 工單。Excel 不負責自動判斷自己屬於哪個項目；使用者必須先選擇項目，再匯入該項目的 Excel 工單。

### 視覺選擇

目前以下項目可選擇「智取櫃」或「門市」視覺：

- 線上／電子BN
- OM
- 直播

未來可以新增視覺。

「門市清單」目前不得自行假設必須使用相同的視覺選擇。是否需要選擇視覺，由該項目已確認的需求決定。

### 主要操作流程

```text
進入開獎秀
→ 選擇要製作的項目
→ 選擇該項目需要的視覺（若適用）
→ 匯入該項目的 Excel 工單
→ 系統依「項目＋所選視覺」自動產生該項目需要的全部 BN
→ 預覽／檢查
→ 必要時微調
→ 下載
```

## 快速取件

### 工具定位

快速取件是另一個完整且獨立的 SPX 工具。

快速取件目前沒有開獎秀的「項目選擇」與「視覺選擇」層級，不得為了統一兩個工具的形式而自行加入。

### 主要操作流程

```text
匯入 Excel 工單
→ 自動產生目前支援的全部 BN
→ 預覽／檢查
→ 必要時微調
→ 下載
```

快速取件目前支援 15 個 BN 版位。15 是目前支援數量，不是永久架構限制；未來可以增加版位。

## 擴充邊界

### 新增同級工具

新工具應作為獨立工具加入 SPX，並登記於根層資料驅動工具清單。入口平台只提供進入方式，不理解新工具的內部內容。

### 新增開獎秀項目

新項目應加入開獎秀內部的資料驅動項目清單，並由開獎秀管理其工單與功能。新增項目不代表新增 SPX 根層工具。

### 新增開獎秀視覺

開獎秀未來可增加視覺。視覺是否適用於某項目，依該項目已確認的需求決定，不自動套用到所有項目。

### 新增快速取件版位

快速取件可在自身工具邊界內增加支援版位。增加版位不應要求開獎秀或其他同級工具配合修改。

## 不屬於本 Architecture Contract 的內容

以下內容由後續需求與 Implementation 決定，本文件不予規定：

- 「開獎秀」與「快速取件」的正式英文資料夾名稱。
- 根層工具清單與開獎秀項目清單的實際檔名、格式及 schema。
- `templates`、`forms`、`assets` 的詳細責任與內部拆分。
- renderer、template 與 geometry 的實際程式架構。
- 開獎秀各視覺在不同項目間的程式共用方式。
- Workspace、JSON 與 Import 的實際資料結構。
- 各工具實際使用的檔案、資料夾與模組拆分。

上述實作不得破壞本文件所定義的入口責任、registry 層級、工具分離、共用字型原則與主要操作流程。
