### 1.1 承接自 Locked Contract 的既有架構邊界（引用，不重新定義）

- 開獎秀是一個完整且獨立的 SPX 工具，最終共用**一套**控制中心。
- 開獎秀目前包含四個項目：線上／電子BN、OM、直播、門市清單。
- 線上／電子BN、OM、直播目前可選「智取櫃」或「門市」視覺。
- 「門市清單」不得自行假設必須使用相同的視覺選擇。
- 使用者必須先選擇項目，再匯入該項目的 Excel 工單；Excel 不負責自動判斷自己屬於哪個項目。
- 開獎秀的項目清單與 SPX 根層工具清單屬於**不同層級**，不得混為同一個 registry 概念。
- 快速取件的修改不得要求開獎秀同步修改，反之亦然。
- `assets/banwords.xlsx` 的既有裁決不代表開獎秀自動需要 banwords 功能。

## 3. 入口與導覽

SPX 首頁既有的工具清單中原本就有「開獎秀」入口，指向 `開獎秀/`。因 `開獎秀/index.html` 現在存在，該入口可正常進入。**本次 Code Commit 未修改 SPX 第一層的任何檔案。**

導覽形式為 **multi-page**：

```text
SPX 首頁
→ 開獎秀/index.html                       Interface 1 選擇項目
   ├── 線上／電子BN ─┐
   ├── OM          ─┼→ 開獎秀/style.html?item=<id>   Interface 2 選擇樣式
   ├── 直播         ─┘        └→ 智取櫃／門市 → （控制台，尚未實作）
   └── 門市清單 ────────────────────────────→ 開獎秀/04_門市清單/index.html
```

Interface 2 的項目狀態透過 URL query param `?item=<id>` 傳遞。門市清單不經 Interface 2，由 Interface 1 以相對路徑 `./04_門市清單/` 直接導向既有 Editor。上述兩個選擇介面仍**不使用** localStorage、sessionStorage、workspace 或任何持久化機制。

## 4. Interface 1 — 選擇項目

檔案：`開獎秀/index.html`（entry script `開獎秀/js/interface-1.js`）

主標題為「開獎秀」，操作說明為「選擇要製作的項目」。

四個項目卡，**不放圖片**，純文字：

| 顯示名稱 | item id | 目前點擊行為 |
|---|---|---|
| 線上／電子BN | `online-bn` | 進入 `style.html?item=online-bn` |
| OM | `om` | 進入 `style.html?item=om` |
| 直播 | `live` | 進入 `style.html?item=live` |
| 門市清單 | `store-list` | 不進樣式選擇；直接進入 `./04_門市清單/` |

Interface 1 的導覽行為：

- `styles.length > 0`：進入 Interface 2。
- `styles.length === 0` 且存在 `directHref`：直接進入該目的地。
- 兩者皆無：保持 fail-closed，停留原頁並顯示「此功能尚未開放」。

返回控制為「← 返回 SPX」，固定導向 SPX 首頁，不使用 `history.back()`。

四張項目卡由 registry 資料驅動產生，HTML 不寫死任何一張卡。

## 5. Interface 2 — 選擇樣式

檔案：`開獎秀/style.html`（entry script `開獎秀/js/interface-2.js`）

主要操作標題為「選擇樣式」，並顯示目前項目名稱，使用者可隨時確認自己正在為哪個項目選樣式。

目前項目透過 `style.html?item=<id>` 傳遞。目前正常流程可進入本頁的 item 為 `online-bn`、`om`、`live`；`store-list` 的 styles 為空，不需選擇樣式，從 Interface 1 直接進入門市清單 Editor。若手動以 `item=store-list` 進入本頁，仍依第 8.2 節 fail-closed。

兩個樣式：

| 顯示名稱 | style id | 目前點擊行為 |
|---|---|---|
| 智取櫃 | `smart-locker` | 因控制台尚未建立而 fail-closed |
| 門市 | `store` | 因控制台尚未建立而 fail-closed |

fail-closed 行為：點擊後**停留原頁、不改變 URL**，顯示「此功能尚未開放」。

**Preview 素材**：目前沒有正式樣式縮圖。兩張樣式卡保留固定 120×120 的空白 placeholder，只負責占住正式 preview 的位置，**不顯示「無縮圖」等文字，也不放入任何代用或假造素材**。未來正式縮圖提供後，只需補上素材並在 registry 填入 preview 來源，卡片 geometry 不需更動。

返回控制為「← 返回」，固定回 Interface 1，不使用 `history.back()`。

兩張樣式卡由 registry 資料驅動產生，HTML 不寫死任何一張卡。

## 6. Registry／資料模型

實際位置：`開獎秀/js/registry.js`，形式為 **ES module**。

這是開獎秀的**項目清單**，與 SPX 根層工具清單屬於不同層級，兩者不得合併或互相引用。

### 6.1 Item

| item id | 顯示名稱 | styles | directHref |
|---|---|---|---|
| `online-bn` | 線上／電子BN | `["smart-locker", "store"]` | — |
| `om` | OM | `["smart-locker", "store"]` | — |
| `live` | 直播 | `["smart-locker", "store"]` | — |
| `store-list` | 門市清單 | `[]` | `./04_門市清單/` |

### 6.2 Style

| style id | 顯示名稱 |
|---|---|
| `smart-locker` | 智取櫃 |
| `store` | 門市 |

### 6.3 已裁決的資料模型規則

- **是否需要樣式選擇，由 `styles.length > 0` 推導**。不存在 `needsStyleSelection` 欄位，避免兩個欄位表達同一件事而互相矛盾。
- **STYLES 是樣式 display data 的單一定義來源**；item 只引用 style id，不重複保存樣式顯示名稱，以避免資料漂移。
- item 各自宣告自己的 styles。目前三個項目的 styles 內容相同，但**不得據此假設它們永遠同步**；調整其中一個項目的 styles 不應牽動其他項目。
- `directHref` 只用於表達不經 Interface 2 的直接導覽目的地。`store-list` 保持 `styles: []`，並使用 `directHref: "./04_門市清單/"`。
- registry 目前只保存這兩個介面需要的最小資料。Excel schema、renderer key、export 設定、workspace 與控制台設定**都尚未裁決，不得提前寫入 registry**。
- registry 具備最小 validation，只檢查會造成 runtime 錯誤的項目：id 非空且唯一、name 非空、`styles` 為陣列、引用的 style id 必須存在、`directHref` 若存在必須為非空字串，且 item 不得同時具有非空 styles 與 `directHref`。validation 失敗時 fail-closed，不渲染錯誤資料。

### 6.4 門市清單 Editor 功能基線

`開獎秀/04_門市清單/index.html` 已正式納入門市清單後續開發的功能基線。後續修改以既有功能不因修改而退化為原則；這不代表目前所有舊 Editor 行為永久 Locked，尚未裁決的細節仍需由 Jamie 裁決。

本輪僅完成平台導覽串接。Editor 新增 `href="../"` 的「← 返回開獎秀」，以固定相對路徑回到目前開獎秀 Interface 1，不使用 `history.back()`。本輪未修改舊 Editor 的資料匯入、解析、renderer、geometry、分頁、背景色、逐頁編輯、放大預覽、JPG、ZIP、暫存、字型或 UI 主體。

## 7. UI／Responsive／Interaction 已裁決規格

### 7.1 共用邊界

- 開獎秀的 CSS 與 JS **完全獨立**：不依賴 SPX 第一層的 CSS，也不依賴快速取件的程式碼。
- 唯一共用的根層資源是正式 **Shopee Noto Sans WOFF2 字型檔**。
- 品牌 accent 為 `#EE4D2D`。不使用 FSS 的品牌色。

### 7.2 Interface 1 版面與互動

延續 SPX 首頁工具卡的視覺。Desktop 卡片 260×156px、padding 24px、border-radius 28px、label 24px Medium、卡片間 gap 24px。

Responsive：

| 視窗寬度 | 排列 |
|---|---|
| 1176px 以上 | 四張同排（4×1） |
| 1175px 以下 | 2×2 |
| 560px 以下 | 卡片縮為 232×140px、gap 16px |
| 最窄 | 單欄 |

**不允許出現 3+1 排列。**

互動：hover 為上浮加輕微放大（`translateY(-4px) scale(1.025)`），active 為輕微回落（`translateY(-1px) scale(1.01)`），transition 220ms。

### 7.3 Interface 2 版面與互動

geometry 與 interaction 參照既有 FSS BN 卡片 precedent，但品牌色改用 SPX orange。

Desktop 樣式卡 geometry：width 180px、min-height 190px、卡片內部 gap 16px、border-radius 22px、preview 120×120px、label 14px。卡片間 gap 18px。

互動：hover 為 `translateY(-4px)`，**不 scale**，**hover 不改變 shadow**，transition 160ms ease。

**嚴禁替樣式卡加入 active transform**（FSS precedent 沒有 active 規則）。

### 7.4 兩頁共同

- 兩頁均支援 `focus-visible`（accent 外框）與 `prefers-reduced-motion`（關閉位移與過場）。
- hover 效果僅套用於真正具備 hover 的指標裝置。
- 真正的頁面跳轉使用 `<a>`；頁內 fail-closed 動作使用 `<button>`。

## 8. Fail-closed 與尚未完成邊界

**總則：所有目前尚不存在的下一層 destination 一律 fail-closed。不得導向不存在的頁面、不得產生 404、不得建立假的控制台或佔位頁。**

返回控制一律使用固定 href，不使用 `history.back()`。

### 8.1 尚無合法目的地時的行為

智取櫃與門市（Interface 2）目前都沒有合法目的地。點擊後停留原頁、不改變 URL，顯示：

> 此功能尚未開放

### 8.2 Interface 2 的參數 fail-closed

| 情境 | 已實作訊息 |
|---|---|
| 缺少 item 參數 | 缺少項目參數。 |
| item 不存在於 registry | 找不到指定的項目。 |
| item 存在但 styles 為空 | 此項目不需選擇樣式。 |
| registry validation 失敗 | 項目清單資料異常，無法載入。 |

以上任一情境都不渲染樣式卡，且**一律保留返回 Interface 1 的出口**。不猜測、不 fallback 到其他 item、不自動轉址。
