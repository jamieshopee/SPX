# SPX 生成器－快速取件 15版位 正式規格

Status: Living Document（逐版位完成後持續更新） 建立日期：2026-09-14

## 1. 文件定位與治理

本文件是快速取件 01～15「逐版位 renderer／visual／encoder／verification」的
唯一集中式正式規格文件。與既有正式文件的治理關係：

1.  `SPX_快速取件_Phase0_完整需求整理.md`：保存需求探索與早期整理。
2.  `SPX_快速取件_Requirement_Specification_v1.0.md`：定義快速取件工具
    整體／共通正式需求。
3.  `SPX_快速取件_Proposal_v1.0.md`：定義共通平台與 implementation
    proposal。
4.  本文件：集中記錄 01～15 各版位最終正式 renderer、geometry、assets、
    typography、per-item differences、encoder、launcher／viewer（如適用）
    與 manual verification status。

共通規則（Workspace、Editor、banwords、Excel Import、KV 共通行為、
Color control、Logo mode contract、Preview／Export contract、Export
readiness gate 等）以既有正式文件為準，本文件不重複收錄；只有與「逐版位
實作」直接相關、或該版位有明確 override 時，才在本文件記錄。

治理規則（自本文件建立起生效）：

-   01～15 的逐版位正式規格統一維護於本文件。
-   後續每完成一個版位的流程：完成 renderer → self-test → Jamie manual
    PASS → Code Commit → 更新本文件該版位章節 → Docs Commit。
-   原則上不再為個別版位建立獨立 Requirement、Proposal、Renderer Spec 或
    Verification Spec，除非 Jamie 明確另行要求。
-   未完成版位章節不得預先填入任何推測規格（含依對位圖反推）。

### 3.14 JPG Encoder

registry `encoderOptions`：

-   quality：1.0
-   maxBytes：245000
-   qualityFloor：0.5
-   searchSteps：7

正式流程：

1.  以 quality 1.0 encode。
2.  blob.size <= 245000 bytes → 直接使用。
3.  超限 → 以 qualityFloor 0.5 encode。
4.  floor 仍超限 → fail-closed（整次 Export 失敗）。
5.  否則 binary search 7 steps。
6.  取符合 maxBytes 的最高 quality。

此策略結構性搬用 FSS BN 現行 JPG compression mechanism（Jamie 裁決）。
快速取件 01 沒有 72 DPI metadata requirement，encoderOptions 不含 dpi，
不做 DPI byte patch；正式輸出規格以 531 × 792 pixels 為準。
